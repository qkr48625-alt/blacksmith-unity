# ⚒️ 대장장이 시뮬레이터 (Unity) — 기획 초안

> 웹 버전(`puhagame/client/src/blacksmith`, 기획서 `puhagame/기획서/blacksmith-project.md`)을 바탕으로 **Unity 전용으로 다시 짠** 기획. 시점은 웹과 같은 **2D/UI 중심**.
> 상태: 초안 (2026-10-29). §10의 정할 것을 정한 뒤 1차 마일스톤을 시작한다.

---

## 1. 방향

웹 버전은 "단검 한 자루를 7공정 미니게임으로 만든다"는 **제작 한 판**이 전부다. Unity 버전은 그 제작 한 판을 **대장간 경영 루프** 안에 넣는다.

| | 웹 버전 | Unity 버전 |
|---|---|---|
| 목표 | 단검 한 자루 완성 | 대장간을 키워 이름난 대장장이가 되기 |
| 한 판 | 7~10분, 단검 1자루 | 하루 단위(의뢰 → 제작 → 납품 → 정산) |
| 무기 | 론델 대거 1종(칼날형 3) | 레시피 여러 종(단검 → 장검 · 도끼 · 창촉 · 투구 …) |
| 재료 | 없음(바로 제련) | 광석 · 숯 · 가죽 · 손잡이 재료를 사고 등급이 점수에 영향 |
| 점수의 쓰임 | 등급 · 보관함 | 의뢰 조건 · 판매가 · 평판 |
| 성장 | 없음 | 도구 업그레이드가 미니게임을 쉽게, 숙련도가 보정 |

**그대로 가져갈 것:** 공정별 미니게임의 손맛(풀무 온도 유지, 망치 힘 모으기, 떨리는 조준, 색 읽기, 크랭크 숫돌, 리듬 바느질 등), 세부 단계 비율 합산, 능력치 식(예리함 · 강도 · 장식미 · 공격력), 검사관 검증표, 돌발 상황, 제작자 마크.

**버릴 것:** 웹 전용 구조(React 컴포넌트 · zustand · localStorage), 한 판에 모든 공정을 매번 다 하는 강제 흐름(§3 참고).

## 2. 핵심 루프 (하루)

```
아침  의뢰판 ── 손님 의뢰 2~4개 중 고르기 (조건 · 기한 · 보수)
  │
낮    시장 ──── 재료 사기 (광석 · 숯 · 가죽 · 손잡이 재료, 등급별 값)
  │
  │   대장간 ── 레시피 고르기 → 공정 미니게임 → 완성품
  │              (하루 작업 시간 한도 안에서 여러 자루, 중간 제품 보관 가능)
  │
저녁  납품 ──── 의뢰 판정(조건 충족 · 검증표) → 보수 · 평판
      정산 ──── 남은 물건 판매 · 도구 업그레이드 · 다음 날로
```

- **작업 시간 한도:** 하루에 쓸 수 있는 "대장간 시간"이 있고, 공정마다 시간을 쓴다. 실제 시간이 아니라 게임 시간이라 미니게임 길이와 따로 논다.
- **중간 제품:** 블룸 · 철 바 · 칼날처럼 공정 사이 결과물을 창고에 둘 수 있다. 정련까지 미리 해 둔 철 바로 다음 날 바로 단조를 시작하는 식.

## 3. 제작 시스템

### 3-1. 레시피 = 공정 순서
- 무기마다 공정 목록과 가중치만 다르고, 공정(미니게임)은 공용 모듈이다. 웹의 `STAGES` · `parts` 구조를 데이터(ScriptableObject)로 옮긴다.
- 예시

| 레시피 | 공정 |
|---|---|
| 단검 | 제련 → 정련 → 칼날 단조 → 열처리 → 연마 → 손잡이 → 칼집 (웹과 같음) |
| 장검 | 제련 → 정련 → 칼날 단조(표적 수 ↑) → 열처리 → 연마 → 날밑 · 손잡이 → 칼집 |
| 도끼 | 제련 → 정련 → 눈 뚫기(펀치) → 날 단조 → 열처리 → 연마 → 자루 끼우기 |
| 창촉 | 제련 → 정련 → 소켓 말기 → 단조 → 열처리 → 연마 |

### 3-2. 미니게임 반복 피로 줄이기
매일 여러 자루를 만들면 같은 미니게임이 반복된다. 웹처럼 매번 7공정을 다 하게 두지 않는다.
- **중간 제품 재사용:** 제련 · 정련은 "철 바 여러 개 한꺼번에" 만들 수 있다(한 번 해서 여러 개).
- **견습생 맡기기:** 업그레이드로 견습생을 두면 공정 하나를 맡길 수 있다. 점수는 견습생 숙련도로 고정(예: 60점)되고 시간만 든다.
- **숙련 보너스:** 같은 공정을 여러 번 하면 그 공정 미니게임이 조금 쉬워진다(구간 폭 · 떨림 보정).

### 3-3. 재료 등급
- 광석(하 · 중 · 상), 숯(소나무 · 참나무), 가죽, 손잡이 재료(나무 · 뼈 · 뿔 + 추가)
- 재료 등급은 해당 공정 점수에 **상한 · 보정**으로 들어간다. 예: 하급 광석은 제련 점수 상한 80, 상급 광석은 제련 +5.

## 4. 의뢰 · 판매

- 의뢰 예시: "송곳형 단검, 예리함 65 이상, 3일 안, 보수 120실링", "장식미 70 이상 의장용 단검", "아무 단검 3자루, 강도 50 이상".
- 판정은 웹의 능력치 · 검증표를 그대로 쓴다. 조건을 넘긴 만큼 보너스, 못 채우면 깎거나 거절.
- 평판이 오르면 까다롭고 보수 큰 의뢰 · 새 레시피가 열린다(기사단 · 영주 의뢰).
- 의뢰 없이 만든 물건은 시장에 팔거나 전시한다. 값 = 등급 × 무기 기본값 × 재료.

## 5. 성장

| 업그레이드 | 효과 (미니게임 연결) |
|---|---|
| 큰 풀무 | 제련 온도 흔들림 ↓ |
| 좋은 망치 | 정련 · 리벳 힘 구간 반폭 ↑ |
| 단조 집게 | 단조 떨림 ↓, 미끄러짐 돌발 확률 ↓ |
| 물통 · 기름통 | 열처리 색 구간 ↑ |
| 고운 숫돌 | 연마 과열 속도 ↓ |
| 견습생 | 공정 하나 맡기기 (§3-2) |
| 창고 · 진열대 | 중간 제품 칸 · 전시 판매 |

## 6. 화면 구성 (2D/UI)

| 화면 | 내용 |
|---|---|
| 마을 지도 | 대장간 · 시장 · 의뢰판 · 검사관 버튼, 날짜 · 돈 · 평판 |
| 의뢰판 | 의뢰 카드 고르기 |

- 완성품 감상은 웹처럼 3D로 돌려 볼지, 2D 그림으로 갈지 정한다(§10).

## 7. 기술 구조

| 항목 | 선택 |
|---|---|
| 엔진 | Unity 6000.6.7f1 (`D:\클로드\blacksmith-unity`) |
| 렌더 | 기본 렌더러. URP 2D 는 스프라이트 · 조명을 쓸 때 넣는다(1차에서는 UI 만 그려서 미룸) |
| UI | UI Toolkit — 메뉴 · 목록 · 미니게임 화면 모두. 화면은 코드로 짜고 모양은 `UI/Main.uss` |
| 한글 글꼴 | 지금은 OS 글꼴(맑은 고딕)을 실행 중에 불러온다. 배포 전에 Noto Sans KR(OFL)을 넣는다 |
| 입력 | Input System (마우스 · 키보드, 스페이스 누르고 있기) |
| 데이터 | ScriptableObject — 공정 · 레시피 · 재료 · 업그레이드 · 의뢰 템플릿 |
| 저장 | JSON (`Application.persistentDataPath`) |
| 소리 | 웹은 Web Audio 합성 → Unity는 짧은 효과음 파일(무료 에셋) 또는 `OnAudioFilterRead` 합성 |

폴더(예정)

```
Assets/_Project/
  Scripts/Core/        게임 상태 · 하루 진행 · 저장
  Scripts/Crafting/    레시피 · 공정 실행기 · 점수 합산 · 능력치 · 검증표
  Scripts/Minigames/   공정 미니게임 (IMinigame: 시작 · 진행 · 점수 + detail)
  Scripts/Economy/     의뢰 · 시장 · 업그레이드
  Scripts/UI/          화면들
  Data/                ScriptableObject 에셋
  Art/ Audio/ Scenes/
```

미니게임 공통 규약: 시작할 때 보정값(업그레이드 · 숙련 · 재료)을 받고, 끝나면 `점수(0~100) + 측정값(detail)`을 돌려준다. 웹의 공정 점수 · 검증표 로직이 그대로 붙는다.

## 8. 1차 마일스톤 (제안)

1. 패키지 세팅(URP 2D · Input System · UI Toolkit), 폴더 · 씬 뼈대
2. 공정 실행 틀 + 미니게임 2개 이식: **제련 풀무질**(누르고 있기) · **정련 접기**(힘 모으기) — 입력 · 게이지 · 점수 규약 검증
3. 레시피 데이터로 "단검" 공정 순서 돌리기 (나머지 공정은 임시 버튼으로 점수 입력)
4. 결과 화면 + 능력치 + 저장

여기까지 하고 손맛을 본 뒤, 나머지 미니게임 이식 → 경영 루프(의뢰 · 시장 · 하루) 순서로 간다.

### 8-1. 1차 마일스톤 구현 (2026-10-29)

- **패키지:** Input System 1.20.1, Active Input Handling = Both. URP 는 미룸(§7).
- **셋업:** 메뉴 `Blacksmith/Setup Project`(또는 배치 모드 `-executeMethod Blacksmith.EditorTools.ProjectSetup.RunBatch`)가 PanelSettings · 공정 7개 · 단검 레시피 · `Scenes/Main.unity` · 빌드 씬 목록 · 플레이어 설정(창 1280×720)을 만든다. 이미 있는 에셋은 덮어쓰지 않는다.
- **데이터:** `Data/Processes/*.asset`(공정 · 세부 단계 · 미니게임 키), `Data/Recipes/Dagger.asset`(공정 순서 · 가중치). 세부 단계의 `minigame` 키를 바꾸면 그 미니게임으로 돈다.
- **미니게임:** 풀무질(`bellows`) · 접기 단접(`fold`) — 웹과 같은 수치. 나머지 13개 세부 단계는 임시 점수 입력(슬라이더). 돌발 상황 · 효과음은 아직 없음.
- **흐름:** 대장간 → 공정 소개 → 세부 단계 → 단계 사이 점수 → 공정 점수(세부 단계 비율) → … → 완성(등급 · 능력치 · 공정별 · 측정값) → 보관함.
- **저장:** `persistentDataPath/blacksmith-save.json`. 세부 단계가 끝날 때마다 저장하고, 대장간에서 이어 하기.

```
Assets/_Project/
  Scripts/Crafting/   ProcessDef · RecipeDef · CraftRun(기록) · Scoring(합계 · 등급 · 능력치)
  Scripts/Minigames/  IMinigame · MinigameRegistry · HoldInput · Gauge · Bellows · Fold · Placeholder
  Scripts/Core/       SaveSystem
  Scripts/UI/         AppRoot · WorkshopScreen · ProcessScreen · ResultScreen · Ui(도우미)
  Editor/             ProjectSetup
  UI/                 Main.uss · Theme.tss · PanelSettings
  Data/ Scenes/
```

## 10. 정할 것

1. **경영 루프 규모** — §2 하루 루프로 갈지, 더 가볍게(의뢰만 받고 만들기) 갈지
2. **반복 피로 대책** — §3-2 세 가지 중 무엇을 넣을지
3. **완성품 감상** — 3D(웹의 Old Fantasy Dagger 모델 재사용) vs 2D 그림
4. **아트** — 직접 그린 단순 도형 · 무료 에셋 · 생성 이미지 중 무엇으로 시작할지
5. **배경 설정** — 웹처럼 15세기 실제 공정 고증 위주 vs 판타지 요소(마법 재료 등) 허용
